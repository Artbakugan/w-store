# ADR 0001: Вибір архітектурного стилю — Модульний моноліт

* **Статус:** Прийнято
* **Дата:** 2026-11-17
* **Контекст:** Проєкт W Store (інтернет-магазин спортивних товарів) розробляється невеликою командою в межах навчального курсу. Бізнес-логіка ще формується, а інфраструктура має залишатися простою та швидкою для локального запуску (Node.js + SQLite).
* **Рішення:** Обрати архітектурний стиль **модульний моноліт** із логічним поділом на доменні контексти та шари (`api/`, `service/`, `domain/`)[cite: 5, 7].
* **Альтернативи:** Пілотний запуск мікросервісів. Відхилено на поточному етапі через зайві накладні витрати на міжсервісну мережеву взаємодію, розподілені транзакції та складність деплою для поточного масштабу системи.
* **Наслідки:**
  * (+) Швидка розробка та тестування без складного налаштування мережі.
  * (+) Єдина база даних SQLite та просте розгортання.
  * (-) Потрібно суворо контролювати межі шарів у коді, щоб не змішувати HTTP-обробку з SQL-запитами[cite: 7, 8].
* **Умови перегляду:** Повернемося до питання виділення окремих мікросервісів (наприклад, Payments або Orders), коли навантаження на каталог перевищить 1000 запитів/сек або з'явиться потреба масштабувати окремі модулі незалежно.
