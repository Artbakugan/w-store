# ADR 0002: Шарова архітектура всередині застосунку

* **Статус:** Прийнято
* **Дата:** 2026-11-17
* **Рішення:** Організувати код бекенду (`backend/`) у три ізольовані шари:
  1. **`api/` (Контролери та маршрути):** приймають HTTP-запити, формують вхідні DTO, викликають сервіси та повертають відповіді згідно з контрактом[cite: 7].
  2. **`service/` (Бізнес-логіка / Use-cases):** виконують валідацію вхідних даних, оркеструють роботу з базою даних та доменними класами, перетворюють моделі у вихідні DTO[cite: 7].
  3. **`domain/` (Доменні сутності):** містять класи сутностей (`Product`, `Order`, `User`, `Payment`) та їхні внутрішні інваріанти[cite: 4, 7].
* **Напрямок залежностей:** Суворо зверху вниз: `api/` $\rightarrow$ `service/` $\rightarrow$ `domain/`[cite: 7].
* **Заборонені зв'язки:**
  * Шару `api/` заборонено напряму імпортувати `db.js` або писати SQL-запити.
  * Шару `domain/` заборонено залежати від Express, HTTP-статусів або бази даних.
